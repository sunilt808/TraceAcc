3. BASEPAPER INTEGRATION - DC-LCG ONTO TRACEACC  [THE ACADEMIC CORE]
--------------------------------------------------------------------------------
 WHY: Your current ML stack (IsolationForest/LOF/DBSCAN) is unsupervised and
 ignores LABELS. The basepaper's DC-LCG is a SUPERVISED dual-view graph neural
 network that beats SOTA by 2%-10% (F1/AUC/AP) on Elliptic, RD, T-Finance.
 Integrating it gives you: (a) a defensible research contribution, (b) real
 benchmark numbers for your report/viva, (c) a genuine detection upgrade -
 it specifically targets the two things your heuristics MISS:
   Challenge 1: DISGUISED nodes (launderers connecting to many licit accounts
                break homophily assumptions)  -> solved by LOCAL VIEW.
   Challenge 2: MULTIHOP flows (>70% of illicit nodes propagate >=2 hops,
                invisible to 1-hop GNNs)        -> solved by CONTEXTUAL VIEW.

 PAPER-MODULE -> CODE MAP (6 deliverables):

 D1. Dynamic Value Field Encoder                        [P1][M]
     Paper Sec IV-A. Discretize transaction amounts into value fields and
     enrich raw features before the network.
     NEW FILE: backend/detectors/dclcg/value_encoder.py
     Hook: called inside the DC-LCG trainer/inference wrapper; also exposed
     standalone so hybrid_engine can use enriched features later.
     Unit target: given N nodes x S raw features -> N x S' (S'=166 for
     Elliptic-compatible runs).

 D2. LOCAL VIEW - Soft-Label-Guided Dynamic Grouping GNN [P1][L]
     Paper Sec IV-B, Eqs (2)-(9): split each node's neighbors into illicit-
     like vs licit-like groups using a soft-label buffer; probability-weighted
     intragroup aggregation + hybrid attention intergroup aggregation.
     NEW FILES: backend/detectors/dclcg/local_view.py
                backend/detectors/dclcg/soft_label_buffer.py
     Key params (from paper): GNN layers Lg (default 2-3), hidden dim 256,
     epochs Eepoch (default 100), soft-label buffer refreshed every epoch.
     Kills Challenge 1 (camouflage/heterophily).

 D3. CONTEXTUAL VIEW - Path Pruning + Transformer Fusion [P1][L]
     Paper Sec IV-C, Eqs (10)-(15): random-walk candidate paths -> prune with
     soft labels -> transformer encoder fuses multipath semantics into node
     embeddings.
     NEW FILES: backend/detectors/dclcg/path_sampler.py (random walks,
                 walk length L=8-16, R walks/node)
                backend/detectors/dclcg/contextual_view.py (Ltm=2 transformer
                 layers, d_model=256, 4 heads)
     Kills Challenge 2 (long-range multihop flows). Complements your existing
     paths.py/cycle.py which are bounded-depth only.

 D4. MUTUAL ATTENTION FUSION HEAD                        [P1][M]
     Paper Sec IV-D, Eqs (16)-(17): bidirectional attention between local
     embeddings C_lv and contextual embeddings C_hv -> fused representation C
     -> classifier. Loss = classification CE + auxiliary consistency
     (Eqs 18-19).
     NEW FILE: backend/detectors/dclcg/fusion.py

 D5. TRAINING + EVALUATION PIPELINE (benchmark proof)     [P1][XL]
     NEW FILES: backend/detectors/dclcg/train.py
                backend/detectors/dclcg/evaluate.py
                backend/datasets_loaders/elliptic_loader.py
                backend/datasets_loaders/tfinance_loader.py
     DATASETS (paper Table I):
       - Elliptic : 203,769 nodes / 234,355 edges / 166 features / 49 time
                    steps / 4.5% illicit  (public download)
       - RD       : Elliptic + 19 deanonymization features, use 20% missing
       - T-Finance: anomalous-account graph (fraud/laundering/gambling)
     METRICS TO REPORT (paper Sec V): AUC, binary F1, AP - per class + macro.
     BASELINES TO INCLUDE IN COMPARISON TABLE (paper uses these families):
       GCN, GAT, GraphSAGE, plus >=2 AML-specific GNNs cited in Sec II.C.
     TARGET: reproduce within +/-3 points of paper numbers on Elliptic;
     document deviations honestly in the project report.
     OUTPUT: results/benchmarks.csv + matplotlib charts auto-generated for
     the final report (F1/AUC bar chart, ablation chart).

 D6. INFERENCE SERVICE + MODEL REGISTRY (production hook) [P1][L]
     - NEW: models/registered_model.py (id, name=dclcg, version, artifact
       path, metrics_f1/auc/ap, trained_at, status=staged|active|retired).
     - NEW: api/routes/models.py (>=4 endpoints):
         GET  /models                     list versions + metrics
         POST /models/{id}/activate       switch active inference model
         GET  /models/{id}/metrics        F1/AUC/AP + confusion matrix
         POST /models/{id}/feedback       push analyst labels for retrain
     - INTEGRATION: analysis.py gains form field model_version (default
       "latest-active"). When a DC-LCG model is active, its illicit
       probability becomes a 6th dimension in hybrid_engine.WEIGHTS
       (proposal: graph .30, behaviour .15, temporal .10, community .05,
        ml_unsup .10, dclcg_supervised .30) - weights become DB-configurable
       (see U1).
     - EXPLAINABILITY BRIDGE: expose mutual-attention weights per node ->
       top contributing neighbors/paths written into Alert.detection_reason
       ("why this account": local-view disguise score + top-3 suspicious
       paths). This turns the paper's black box into auditor-friendly output
       and is a differentiator for your viva demo.
